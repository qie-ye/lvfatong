## 二、模块一：数据分析 Dashboard（1.5周）

### 2.1 目标

构建运营数据可视化面板，帮助团队了解产品使用情况，指导产品迭代。

### 2.2 功能清单

| 功能 | 说明 | 数据来源 |
|------|------|----------|
| **用户概览** | 总用户数、日活、周活、月活 | user 表 |
| **查询统计** | 日查询量、查询趋势、高峰时段 | chat_messages 表 |
| **热门问题** | 高频查询词、热门法律领域 | user_behaviors 表 |
| **AI 效果** | 回答准确率、用户满意度 | answer_feedback 表 |
| **推荐效果** | 推荐点击率、转化率 | recommendation_logs 表 |
| **合同分析** | 分析数量、风险分布 | contract_documents 表 |

**前端**：
- 新增 `DashboardView.vue` 管理后台页面
- 使用 ECharts 图表展示数据
- 支持时间范围筛选

### 2.4 API 接口

## 三、模块二：安全与合规（2周）

### 3.1 目标

满足企业级安全要求，提升产品可信度，为进入企业市场做准备。

### 3.2 功能清单

| 功能 | 说明 | 实现方式 |
|------|------|----------|
| **数据加密** | 敏感字段加密存储 | AES-256 加密 |
| **审计增强** | 操作日志、数据访问记录 | AOP 切面 |
| **隐私保护** | 用户数据脱敏、导出/删除 | 接口 + 定时任务 |
| **权限细化** | 数据行级权限、API 级权限 | Spring Security |
| **登录安全** | 登录失败锁定、异地登录提醒 | Redis 计数器 |
| **接口限流** | API 调用频率限制 | 令牌桶算法 |

### 3.3 技术方案

**数据加密**：
```java
// 敏感字段注解
@Encrypted
private String idCard;

// JPA 自动加解密
@EntityListeners(EncryptionListener.class)
```

**审计增强**：
```java
// 审计注解
@AuditLog(action = "DELETE", resource = "用户数据")
public void deleteUser(Long userId) {
    // 业务逻辑
}
```

**隐私保护**：
```java
// 数据导出（GDPR 合规）
@GetMapping("/users/me/export")
public ResponseEntity<byte[]> exportUserData(Long userId);

// 数据删除
@DeleteMapping("/users/me")
public ApiResult<Void> deleteUserData(Long userId);
```

### 3.4 API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/users/me/export` | 导出个人数据 |
| DELETE | `/api/users/me` | 删除个人数据 |
| GET | `/api/admin/audit-logs` | 审计日志查询 |
| POST | `/api/admin/audit-logs/export` | 审计日志导出 |


## 四、模块三：知识图谱（3周）

### 4.1 目标

构建法律知识图谱，增强实体关系推理能力，提升复杂问题的回答质量。

### 4.2 功能清单

| 功能 | 说明 | 实现方式 |
|------|------|----------|
| **图谱构建** | 从法条/案例中抽取实体和关系 | NLP + 规则引擎 |
| **图谱存储** | 存储法律实体关系 | Neo4j |
| **图谱查询** | 支持图谱问答 | Cypher 查询 |
| **图谱可视化** | 展示实体关系图 | ECharts Graph |
| **图谱增强 RAG** | 检索时考虑实体关系 | 混合检索 |

### 4.3 技术方案

**图数据库选型**：Neo4j 5.x

**实体类型**：
- 法律法规（Law）
- 法条（Article）
- 案例（Case）
- 法律概念（Concept）
- 律师（Lawyer）
- 用户（User）

**关系类型**：
- 引用（CITES）
- 相似（SIMILAR_TO）
- 适用（APPLIES_TO）
- 包含（CONTAINS）
- 专长（SPECIALIZES_IN）

### 4.4 图谱架构

```
┌─────────────────────────────────────────────────────────┐
│                    知识图谱系统                          │
├─────────────────────────────────────────────────────────┤
│  数据源：法条、案例、FAQ、律师信息                        │
│      ↓                                                   │
│  实体抽取：NER 识别法律实体                               │
│      ↓                                                   │
│  关系抽取：规则引擎 + AI 识别关系                         │
│      ↓                                                   │
│  图谱存储：Neo4j 存储实体和关系                           │
│      ↓                                                   │
│  图谱应用：问答、检索、可视化                             │
└─────────────────────────────────────────────────────────┘
```

### 4.5 API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/knowledge-graph/entities` | 实体列表 |
| GET | `/api/knowledge-graph/entities/{id}` | 实体详情 |
| GET | `/api/knowledge-graph/entities/{id}/relations` | 实体关系 |
| GET | `/api/knowledge-graph/search` | 图谱搜索 |
| POST | `/api/knowledge-graph/query` | 图谱问答 |
| GET | `/api/knowledge-graph/visualize/{id}` | 可视化数据 |

## 五、模块四：多模态支持（2周）

### 5.1 目标

扩展输入方式，支持语音、图片、扫描件等多种输入形式。

### 5.2 功能清单

| 功能 | 说明 | 实现方式 |
|------|------|----------|
| **语音输入增强** | 更准确的语音识别 | 讯飞/阿里云 ASR |
| **语音播报** | AI 回答语音播放 | TTS 服务 |
| **图片 OCR** | 合同照片文字识别 | OCR 服务 |
| **扫描件识别** | PDF 扫描件文字提取 | OCR + PDF 解析 |
| **图片问答** | 支持图片上传提问 | 多模态模型 |

### 5.3 技术方案

**语音识别**：
- 主要：讯飞 ASR（已有集成）
- 备选：阿里云 ASR

**OCR 服务**：
- 方案一：百度 OCR API
- 方案二：Tesseract 本地部署
- 方案三：PaddleOCR 本地部署

**TTS 服务**：
- 主要：讯飞 TTS
- 备选：阿里云 TTS

### 5.4 API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/speech/asr` | 语音识别 |
| POST | `/api/speech/tts` | 语音合成 |
| POST | `/api/ocr/recognize` | 图片 OCR |
| POST | `/api/ocr/contract` | 合同扫描件识别 |
| POST | `/api/multimodal/chat` | 多模态问答 |
